# ezhex · 笔记（已解：文件名是 flag 三段的 CRC32）

## 关键点
- 附件 `1 (4).zip` 解出三个 **0 字节** 文件：
  `94900dad_4.txt`、`1185397d_4.txt`、`ed3e85c8_4.txt`。
- zip 结构正常（无注释、无 extra field、无隐藏条目；每个空文件只有 deflate 空块 `03 00`），
  所以信息只在文件名里。
- 题面提示「三个文件的名字 hex 一下」：把名字里的 8 位 hex 当数值，正好是 3 个 32-bit 值：
  `0x94900dad`、`0x1185397d`、`0xed3e85c8`。
- **CRC32**！32 bit 的“短指纹”，短串原像可爆破：
  - `crc32(b"nex{") = 0x94900dad`
  - `crc32(b"ezCr") = 0x1185397d`
  - `crc32(b"c32}") = 0xed3e85c8`
- 组合：`nex{` + `ezCr` + `c32}` = **`nex{ezCrc32}`**（13 字符，符合 flag 格式）。

## 判定
- 三段分别由 CRC32 爆破出原像（长度 1..4、字符集 `[A-Za-z0-9_{}]`，共 3.9 s）；
- 每段 CRC32 回代与文件名 hex 精确相等（`1185397d`/`94900dad`/`ed3e85c8` 三个 OK）；
- 拼接后 `nex{...}` 正则命中、以 `}` 结尾。

## 失败分支（排除理由）
- 先怀疑六个方向：zip 注释/extra 字段（均空）、CRC 字段（全 0）、单字节 CRC32（无命中）、
  文件名自身 crc32/md5/sha1/sha256（都不等于名字里的值）、三个 32-bit 值 XOR（`0x682bb118` 无意义）、
  GBK/UTF-8 直接解码（0x11/0x0d 等控制字符）——全部排除。
- 关键转折：注意到“文件名 = 8 位 hex”且“文件为空”，想到空文件没有内容、名字却像 32-bit 校验值，
  才想到 CRC32 的短串原像爆破。

## 可复用 TTP
- “空文件 + 名字是 hex/数字” ⇒ 先想 hash/CRC 原像；CRC32 只有 32 bit，短串（≤4~5 字节）可爆破。
- 爆破字符集要按题目 hint 收窄（flag 字符集 `[A-Za-z0-9_{}]`，64 个字符，4 字节 1.6e7 次，几秒）。
- 分段 CRC 的题目：先各自爆原像，再按 `nex{` 前缀 / `}` 后缀排列组合。
