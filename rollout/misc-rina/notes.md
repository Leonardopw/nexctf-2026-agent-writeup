# 如果你看扁我（rina）· 笔记（已解）

## 关键点
- 附件 `rina.png`，1,287,562 字节；IHDR = 2150×1950、8-bit RGB、非隔行，所有 chunk CRC 都正确
  （作者改高度后重算过 IHDR CRC，所以“CRC 不匹配”这条线索不成立）。
- 题面「如果你看扁我」+ 提示「200」：看扁 = 被裁掉高度。
- 用 IDAT 解压长度反推：行字节 = 1 + 2150×3 = 6451；
  期望 1950×6451 = 12,579,450，实际解压 13,869,650 —— **多出 200 行**（与提示 200 完全一致）。
- 修复：把 IHDR 高度改回 2150、重算 IHDR CRC，Pillow 即可解码 2150×2150；
  底部 200 行就是被“看扁”掉的区域，里面有红色文字 flag：
  `nex{k0mAtSu_R1na}`

## 判定
- 多出的字节数恰好是整 200 行（1290200 = 200×6451），不是填充/垃圾数据；
- 还原后图片可正常解码、无 CRC/解码错误；
- 底部 200 行肉眼可读 `nex{k0mAtSu_R1na}`，格式与正则一致。

## 失败分支（排除理由）
- 先查 IHDR CRC：**匹配**，说明作者改高度时重算了 CRC，不能靠 CRC 报错定位；
- binwalk/zsteg 类隐写：不必，IDAT 长度差已直接暴露 200 行；
- 只看 1950 高的图：看不出异常，flag 完全在裁掉的底部。

## 可复用 TTP
- PNG 高度改小题：**先解压 IDAT 算真实行数**（`len(data)/(1+w*bpp)`），比看 CRC 可靠；
  作者常重算 IHDR CRC，CRC 通过不代表尺寸没被改。
- 还原只需改 IHDR height + 重算 CRC（zlib.crc32(raw[12:29])），IDAT 不用动。
- 相似套路：宽度改小（右边被裁）、隔行/交织参数被改。
